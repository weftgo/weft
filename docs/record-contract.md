# The record contract

What weft's observability pipeline emits, and what `obsdb` reads back
into a run, stated so that someone without the Go source can build a run
page from stock OTLP — or make a non-Go agent emit records weft's Studio
reads as its own.

**This page is the authority.** It restates, in one place, the contract
that ADR 0016 (the spans), ADR 0024 (the records and the identity chain)
and ADR 0028 (the request record, the compaction view, the badges)
decided; the ADRs keep the *why*. Two things pin it to the code:

- `obsdb/model.go` — the attribute constants, `DeriveSpan`,
  `DeriveRecord` and `MetaOf` — and `TestRecordContractDocNames`
  (`obsdb/contract_test.go`), which fails when this page names a `weft.*`
  or `gen_ai.*` key no emitter or reader spells, or when `obsdb/model.go`
  spells one this page does not name.
- The conformance fixtures, `obsdb/testdata/contract/<case>/`: an OTLP/JSON
  export (`traces.json`, `logs.json`) and `expect.json`, the run rows any
  conforming store derives from it. `TestContract` checks every case on
  SQLite and `TestContractClickHouse` on ClickHouse (with
  `WEFT_CLICKHOUSE_DSN`). The inputs are real pipeline output,
  regenerated by `go test ./obsdb -run 'TestContract$' -update-contract`
  (the generator's own flag, not the shared `-update`) and normalised so
  a regeneration with no code change is byte-identical (§10); only the
  stock-GenAI case is hand-written.

Changing a name, a kind or a rule on this page is a schema change: it
needs an ADR amendment (ADR 0024's rule), the fixtures regenerated, and
this page in the same change.

## 1. The transport

Everything is OpenTelemetry: **spans** through the trace API and **log
records** through the Logs API, exported as OTLP. Studio's receiver takes
OTLP/HTTP at `POST /v1/traces` and `POST /v1/logs`, protobuf or JSON,
optionally gzip, at most 16 MiB decompressed per request. OTLP/JSON trace
and span ids are lowercase hex (`traceId` 32 digits, `spanId` 16).

- A span or record **is weft's** when it carries `weft.run.id`. Anything
  else is stored as it came — non-weft spans in the trace view, non-weft
  log records as the run's app logs when they share its spans — and never
  becomes a run, except by §9.
- Attribute values are OTLP `AnyValue`s. Readers accept an integer
  attribute as an int, a double, or a decimal string (`"3"`): the core
  stamps run metadata as strings, so `weft.turn` arrives as `"3"`. A
  boolean flag accepts `true` or the string `"true"` (`weft.playground`
  arrives as `"true"`).
- Resource: `service.name` (the run row's service) and `weft.version`
  (the framework version that built the pipeline). The instrumentation
  scope is `github.com/weftgo/weft/core` with the core's version.
- Trace and span ids are **correlation, not identity**: they are zero
  without an SDK and missing when sampled out. Every join a reader needs
  is on a weft id (§2). A record carries the trace and span id of the
  context it was emitted on — for most kinds the run's `invoke_agent`
  span, not the span the record describes (§4).

## 2. The identity chain

Carried as attributes on every span and record of a run (the run's
metadata rides every span and record verbatim):

| Link | Attribute | Type | Minted by | Notes |
|---|---|---|---|---|
| run | `weft.run.id` | string | the core | 32 lowercase hex digits for a plain run; `<session>-t<n>` for a `thread` turn; `<parent>/<step>/<call id>` for a Subagent child (below); or the caller's own, through `core.RunID` (any string — it must not start with `otel-`, the derived-run prefix of §9; nothing enforces that — the core accepts any id, and obsdb does not guard it either: a weft run whose id has the exact derived shape, `otel-<32 hex>-<16 hex>`, would have its spans read as a derived run's, by trace — `obsdb.ParseStockRunID`) |
| parent run | `weft.parent.run.id` | string | the core | on a Subagent child's `invoke_agent` span and its `run_start` record only |
| parent call | `weft.parent.call.id` | string | the core | the parent's tool call the child ran under (its `gen_ai.tool.call.id`) |
| session | `weft.session.id` | string | `thread`, or the app via `Metadata` | mirrored as `gen_ai.conversation.id` and `session.id` on every span and record the core emits for the run (and so on the heartbeat, which copies `run_start`'s attributes) — not on `thread`'s session compaction marker, which carries `weft.session.id` alone (§4) |
| turn | `weft.turn` | int (as a string) | `thread` | the turn number the run id was minted from (`-t<n>`) |
| public id | `weft.public_id` | string | `thread.PublicID`, or the app via `Metadata` | the browser-facing id a panel token is scoped to |
| agent | `gen_ai.agent.name` | string | the core | absent for an unnamed agent |
| agent config | `weft.manifest.hash`, `weft.version` | string | the core | on the `invoke_agent` span and the `run_start` record |
| step | `weft.step.index` | int | the core | 0-based model-call ordinal within the run |
| tool call | `weft.tool.seq` (+ `gen_ai.tool.call.id`) | int | the core | `weft.tool.seq` is the `tool_start` event's `seq` |
| event / delta | `weft.event.pos` / `weft.delta.pos` | int | the core | two separate counters (§4) |
| end user | `enduser.id`, mirrored `user.id` | string | the app via `Metadata` | attribution, not part of the chain |

**Subagent children.** A `core.Subagent` tool runs another agent as a
child run with the id `<parent run id>/<step>/<call id>`, or
`<parent run id>/resume/<call id>` when the call ran under `Approve`. The
id is self-describing: a run whose id has the form `<id>/…` is a core
Subagent child of run `<id>`, and Studio's cost split subtracts exactly
those children's usage from the parent's (the parent's own usage figure
includes every child's). The link is still carried explicitly
(`weft.parent.run.id`, `weft.parent.call.id`); a reader never parses an
id to find a parent. The child's `invoke_agent` span is a child of the
parent's `execute_tool` span. A `thread/pool` child is a separate session,
not a Subagent child: no `/`, no parent attributes, its link is the
session metadata below.

**Session lineage and playground marks** — run metadata, so on every span
and record of the run, all strings. The last column is where a reader
puts each (§6): a run-row column, or the row's `meta` map, which Studio
reads them from:

| Attribute | Set by | Meaning | Run row |
|---|---|---|---|
| `weft.session.title` | `thread` (`SetInfo`'s title) | the session's title (`Session.Title`) as the turn started, absent before one was set — a label, not content: it survives a content-off destination (the `session_title` fixture). A fork carries the newest title on the copied path at the fork point (a title set after the fork point, or on another branch, is not carried); the title is the newest across the whole entry tree, so a `Branch` back past a `SetInfo` keeps the newer title; a held compaction marker (no run of the session produced the context) goes out under the next run's own metadata, and the fallback for a run this Session did not see (before a reopen, or past its recent-runs list) stamps the title current when emitted | `meta`; the session row's `title` (§6) |
| `weft.session.forked_from` | `thread` (`Fork`) | `<origin session>#<entry id>` | `meta` |
| `weft.session.parent` | `thread/pool` | the parent session of a pool child | `meta` |
| `weft.session.parent_call` | `thread/pool` | the parent's tool call that spawned it, when known | `meta` |
| `weft.playground` | `weft/runtime` | `"true"` on a run Studio's playground started (never part of a session) | column `playground` |
| `weft.playground.command` | `weft/runtime` | the playground command id | `meta` |
| `weft.playground.actor` | `weft/runtime` | who issued it, when known | `meta` |
| `weft.experiment.id` | `weft/runtime` | the saved experiment the run belongs to | column `experiment_id` |
| `weft.forked_from` | `weft/runtime` | `<source run>#<from step>`: the run this replay continues | column `forked_from` |
| `weft.replay.view` | `weft/runtime` | a replay from step N > 0: `transcript`, `compacted:<index>`, `derived` or `unknown` | `meta` |
| `weft.edits` | `weft/runtime` | the transcript edits a replay applied | `meta` |
| `weft.page_url` | `weft/scope` | the app page the run was started from (sanitised) | `meta` |
| `weft.approval.actor` | `thread` (a resume turn: each decision's signing key id, else its `Who`), `weft/runtime` (the decide command's actor: `panel:<public id>`, `server`, `local`), the app via `Metadata` | who decided the calls this run resumes — distinct actors in call order, comma-joined; absent when the decisions name nobody. Metadata, so it survives content-off like every metadata pair — verbatim on every span and record, to every destination (§2's caller pairs: no content policy strips metadata); put an opaque id in `Who` / `KeyID`, not an email or a name. `thread` owns it: set on every run that applies recorded decisions (a resume turn), `""` on every other turn | `meta` |
| `enduser.id` | the app via `Metadata` | the end user (§2's table) | `meta` (its mirror `user.id` is not) |

**A session stamps its own identity, empty = none.** Run metadata
rides the context into every run started under it, so a session's turn
started inside another run (another session's tool handler, a pool
child's turn) would inherit that run's pairs. `thread` therefore sets
every key a session owns on each of its runs — `weft.public_id`,
`weft.session.title`, `weft.session.forked_from`, `weft.session.parent`,
`weft.session.parent_call` — to the session's own value, `""` when it
has none, and the core reads an empty value as *none*: it removes the
inherited pair and is never stored, never on a span or record
(`core.Metadata`). A session without `thread.PublicID` nested in pub_s's
turn is not pub_s's: no panel token of pub_s lists or reads it, and the
playground's app-turn verbs refuse it as not a turn of a session with a
public id. A plain `Generate` in the same tool handler is the enclosing
turn's work and inherits everything. A session's keys win over the
caller's, so a `thread` session's public id is `thread.PublicID`'s
alone (the `Metadata` run option sets one on runs a session does not start).
Readers hold the same rule for
producers that send an empty value anyway: obsdb's `MetaOf` drops an
empty string, the `public_id` column's `""` is no public id (no scope
matches it; `ResolvePublicID("")` is `ErrNotFound`).

**What lands in `meta`.** `obsdb.MetaOf` keeps every **string**-valued
attribute of any span or record of the run (merged) whose key is not on
one closed exclusion list. Being named on this page does not keep a key
out of `meta`; only that list does. It is, exactly:

| Never in `meta` | Keys |
|---|---|
| identity (§2) | `weft.run.id`, `weft.parent.run.id`, `weft.parent.call.id`, `weft.session.id`, `weft.public_id`, `weft.turn`, `gen_ai.agent.name` |
| run-row columns | `weft.playground`, `weft.experiment.id`, `weft.forked_from`, `weft.resumed_from`, `weft.version`, `weft.manifest.hash`, `weft.instructions.hash` |
| record keys (§4) | `weft.record`, `weft.event.type`, `weft.event.pos`, `weft.delta.pos`, `weft.messages.index`, `weft.messages.count`, `weft.messages.input`, `weft.messages.reason`, `weft.messages.from_seq`, `weft.messages.to_seq`, `weft.request.index`, `weft.prompt.index`, `weft.tools.index`, `weft.raw.index`, `weft.system.hash`, `weft.catalog.hash`, `weft.compaction.hash`, `weft.compaction.scope`, `weft.content`, `weft.content.truncated_bytes`, `weft.step.index`, `weft.tool.seq`, `weft.attempt.index`, `weft.latency_ms` |
| span keys (§3) | `weft.run.steps`, `weft.run.pending`, `weft.run.denied`, `weft.run.stop_reason`, `weft.stop.raw`, `weft.model.tool_calls`, `weft.stream`, `weft.ttft_ms`, `weft.attempt.retry_after_ms`, `weft.tool.approved`, `weft.tool.pending`, `weft.tool.result_bytes`, `weft.tool.truncated_bytes`, `weft.tool.input_error`, `weft.tool.retry`, `weft.tool.retry_budget`, `weft.panic.layer`, `weft.metadata.dropped`, `weft.tap.panics`, `weft.resume.calls`, `weft.tool.denied`, `weft.tool.denied_kind`, `weft.override.hash` and every `weft.override.*` key of §3 |
| GenAI keys (§8) | `gen_ai.operation.name`, `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.response.model`, `gen_ai.response.finish_reasons`, the five `gen_ai.usage.*` keys, `gen_ai.tool.name`, `gen_ai.tool.call.id`, `error.type` |
| mirrors | `gen_ai.conversation.id`, `session.id`, `user.id` |

Everything else — the caller's own `Metadata` keys, `enduser.id`, and
the `meta` rows of the table above — lands in `meta` as a string, as
does any other `weft.` key outside the list (a module's own). A
non-string attribute outside the list is dropped from `meta` on SQLite
and stringified on ClickHouse, which is why every non-string contract
key is on the list. `weft.metadata.dropped` (int, `invoke_agent` span)
says how many pairs the metadata limits dropped.

A known limit on ClickHouse (debt, not changed yet): a run's `meta` there
is the greatest of its contributing rows' JSON maps compared as strings
(`max(Meta)` in the runs view) — one row's map wins, the maps are not
merged as on SQLite. The spans and records the core emits for a run
carry the same map, so this is invisible for them, with one exception:
the compaction marker a reopened `thread` session emits for a run it did
not see (a forked or pool session's `Compact` after a reopen) carries
only that session's `weft.session.*` keys, whose JSON sorts above a map
starting `{"tenant…`, so it can win and drop the caller's pairs from that
run's ClickHouse `meta`.

## 3. Spans

Four span kinds, named by the GenAI conventions (`<operation> <name>`).
Spans carry ids, names, counts, durations, reasons and error *types* —
never content (ADR 0016 O7). Every weft span carries `weft.run.id` and the
run's metadata.

### `invoke_agent` — the run

Name `invoke_agent <agent>` (or `invoke_agent`), kind Internal; the root
of the run's tree (a child of the parent's `execute_tool` for a Subagent
child). It ends when the run does, however the run ends.

| Attribute | Type | When |
|---|---|---|
| `gen_ai.operation.name` | string `invoke_agent` | always |
| `weft.run.id` | string | always |
| `gen_ai.agent.name` | string | named agents |
| `gen_ai.provider.name` | string | the model reports a provider (`openai`, `anthropic`, `gcp.gemini`, else verbatim) |
| `gen_ai.request.model` | string | the model reports a name |
| `weft.instructions.hash` | string, sha256 hex | always (on runs written since ADR 0028; the empty string's hash for no instructions) |
| `weft.parent.run.id`, `weft.parent.call.id` | string | Subagent children |
| `weft.manifest.hash` | string | named agents |
| `weft.version` | string | always |
| `weft.logs.bridged` | int | at start, while the pipeline has a live slog bridge (a `Pipeline.SlogHandler`, `otel.Slog`'s wrap while it is still `slog.Default`'s handler, or any handler that has teed a line into this pipeline; set by `weft/otel`'s span processor, not the core), and only on the copy a destination that takes app logs (`otel.AppLogs`) exports — a content-off sink, an `AppLogs(false)` one or a third party not opted in receives the span without it: the lines the bridge had emitted so far. Its presence is the mark — "this store holds the run's bridged lines"; a stored root without it ran with no bridge reaching this store, which the logs route's hint reads (§7); not caller metadata (`obsdb.MetaOf` skips it) |
| `weft.metadata.dropped` | int | the metadata limits dropped pairs (§6 `problems`' `metadata_dropped` token: the run document's `truncated` hole, cause `metadata_cap`, §7) |
| `weft.resumed_from` | string | the run this one resumes, as `core.ResumeOf` named it (UX-E-17): `thread` passes it on every resume turn (the parked turn's run id), `weft/runtime` on every resume it runs, an app resuming a plain `Generate` passes the parked `RunResult.ID` — the core cannot infer it, a transcript carries no run id. §6 `resumed_from` / `resumed_by` |
| `weft.resume.calls` | string | a run fed decisions that resumes parked calls: each parked call, in call order, as `<call id>=<kind>`, comma-joined — `approved` (`Approve`), `denied` (`Deny`), `resolved` (`Resolve`, `ResolveError`), `no_decision` (left undecided: rule 12's `DENIED: no decision`). The kind is the decision, not the outcome: an `approved` call may still fail, or park again. Ids and enums only — never a reason or a resolved payload (the transcript's). Capped at 32 calls: past them the value ends `,…+k`, `k` the calls not listed. `no_decision` comes only from a plain core `Generate`: `thread` writes an undecided call as an explicit `Deny(id, "no decision")`, so a thread resume reads `denied` there, and `weft/runtime` resumes a parked run only once every pending call has its decision |
| `weft.override.hash` | string, sha256 hex | a run option changed the agent's configuration (the experiment fingerprint) |
| `weft.override.instructions` | bool `true` | the instructions were replaced (the text is never on a span) |
| `weft.override.tools` | string, comma-joined sorted names | `OnlyTools` |
| `weft.override.model` | string `<provider>/<name>` (the bare name without a provider) | `UseModel` |
| `weft.override.park_on`, `weft.override.park_all_except` | string | `ParkOn` / `ParkAllExcept` |
| `weft.override.thinking` | string | a per-run thinking level |
| `weft.override.tool_choice` | string | a per-run tool choice |
| `weft.override.params` | string (JSON) | per-run sampling params |
| `weft.override.max_steps`, `weft.override.parallelism` | int | lowered per run |
| `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens` | int | at end: run totals, Subagent children included |
| `gen_ai.usage.cache_read.input_tokens`, `gen_ai.usage.cache_creation.input_tokens`, `gen_ai.usage.reasoning.output_tokens` | int | at end, each only when non-zero |
| `weft.run.steps` | int | at end |
| `weft.run.events` | int | at end, always: the durable `event` records the run handed to its LoggerProvider (§4's `weft.event.pos` counter's final value) — 0 when no logger was wired or it enabled none. A reader compares it with what it stored (§6 `events_emitted`, §7 `gap` / `events_lost`) |
| `weft.run.messages` | int | at end, always: the growth `messages` records emitted (views excluded) — 0 when content capture was off or no logger was wired. Informational: a content-off destination legitimately stores none (§5) |
| `weft.run.pending` | int | at end, when calls are parked for approval |
| `weft.run.denied` | int | at end, on the resuming run (a run fed decisions), when it denied parked calls — an explicit `Deny` and every call left undecided ("no decision"): they have no event (ADR 0007) and, since U13.1, a zero-length `execute_tool` span each marked `weft.tool.denied` — which a reader does not count again: this count stays their carrier (§6 `problems.denied`). Not a `Resolve` (a result computed outside the process); not an `mw.Allow` refusal (a policy middleware's `DENIED` has its own `execute_tool` span, counted from there); not the calls `Repair` fills with an error result when a transcript with parked calls returns with a new prompt instead of decisions — those are uncounted |
| `weft.tap.panics` | int | at end, when observers panicked during the run and were contained: taps, `OnMessages` observers, a record or report the logger or tracer failed to build — the run's share of `Agent.TapPanics` (`OnRunEnd` observers run after the span ended: theirs reach `TapPanics` alone). The run is unchanged; an observer the app relies on saw less (§6 `problems.tap_panics`) |
| `weft.run.stop_reason` | string | at end: the last step's `stop`, `tool_calls`, `max_tokens` |
| `weft.run.stopped_by` | string | at end, what ended the run: a fired `StopWhen` condition's manifest name (`has_tool_call:<tools>`, `step_count_is:N`, `output_submitted`, a custom condition's `String()`, else `custom`), `final_answer`, `parked`, `max_steps`, `usage_limit`, `loop_detected`, `model_retries_exceeded`, `canceled`; absent on a failure no control decided (a model error, …: `error.type` names it). On a failed run this span is its only carrier (no `run_finish`) |
| `weft.cancel.cause` | string | at end, a `canceled` run whose cause names itself: `thread.interrupted`, `thread.closed`, `studio.cancel`, `app.shutdown` (the runtime link's own shutdown felling a run it started) (a `core.CancelCause` — any cause with a `Kind()`), `deadline`; absent for a plain cancel (a `Stream` consumer breaking out of its loop among them) |
| `error.type` | string | on failure, a closed table (ADR 0016's): `max_steps`, `usage_limit`, `loop_detected`, `model_retries_exceeded`, `model_contract`, `duplicate_tool`, `nil_tool`, `no_output`, `stream_idle`, `unsupported`, `model_requests_denied`, `run_panicked`, `model_error` (a provider failure, the default), and the context errors' names `context.Canceled` / `context.DeadlineExceeded` (a reader's run row reads both as `cancelled`, §6) |

Status: `Ok` on success (a run parked at an approval succeeded), `Error`
with the error text as the description and a recorded exception on
failure.

| Attribute | Type | When |

### `attempt` — one try inside a model call

Name `attempt`, kind Client, child of `chat`; only when the model chain
reports attempts (`mw.Retry`, `mw.Fallback`, an adapter reporting its SDK's
retries). `weft.run.id`, `weft.step.index`, `weft.attempt.index` (1-based,

`gen_ai.provider.name`, `gen_ai.request.model`,
`weft.attempt.retry_after_ms` (when the provider asked to wait),
`weft.attempt.layer` (`core.AttemptInfo.Layer`: `fallback` on a request

failure.

### `execute_tool` — one tool call

Name `execute_tool <tool>`, kind Internal, child of `invoke_agent`.

| Attribute | Type | When |
|---|---|---|
| `gen_ai.operation.name` | string `execute_tool` | always |
| `gen_ai.tool.name`, `gen_ai.tool.call.id` | string | always |
| `weft.run.id`, `weft.step.index`, `weft.tool.seq` | string, int, int | always |
| `weft.tool.approved` | bool `true` | a call resumed by `Approve` |
| `weft.tool.denied`, `weft.tool.denied_kind` | bool `true`, string | a parked call the resume denied: `denied` (`Deny`) or `no_decision` (left undecided). The span is zero-length (start = end, the moment the resume decided it), carries `weft.step.index` 0 and no `weft.tool.seq` (no `tool_start`: the call never ran), `error.type` `DENIED`, status `Error` — never the reason |
| `weft.tool.result_bytes` | int | at end, a successful result only (not an error result, not a parked call): the length of the result the model sees (after the result cap) |
| `weft.tool.pending` | bool `true` | at end: the call was parked for approval |
| `weft.tool.truncated_bytes` | int | at end, a result or an error result the result cap (`MaxResultBytes`) cut: the bytes it removed — the number the model's `…[truncated N bytes]` marker names; absent when nothing was cut |
| `error.type` | string | an error result, in this order: the `ToolError` code when the chain produced one (`INVALID_INPUT`, `NO_SUCH_TOOL`, `DENIED` from a policy middleware such as `mw.Allow`, `RETRY`, a handler's own code); `timeout` (the call's `Timeout` passed); `panic` (a contained panic in the handler or its middleware); the context error's name when the run's cancellation reached the call (`context.Canceled`, `context.DeadlineExceeded`); the error's own `ErrorType()` string when an error in its chain declares one (a convention: `weft/mcp`'s `mcp_transport` — the `tools/call` did not complete — and `mcp_tool_error` — the server answered `isError`); else `tool_error` |
| `weft.tool.retry`, `weft.tool.retry_budget` | int, int | `error.type` `RETRY` (`core.ModelRetry`) counted by the loop: the tool's consecutive RETRY count with this result (1-based; assigned after the step's batch, in call order, exactly as the guard counts: a success of the tool resets it, so a RETRY in a batch that also holds a success of the same tool carries no mark; the span of a marked call ends after its batch, timestamped when the call returned, so its duration is still the call's; on the span only — the `tool_finish` record is written as the call finishes, before the mark is known) and the run's `MaxModelRetries`. The loop fails the run (`model_retries_exceeded`, its error naming both: `tool "x" retried 3 times, past MaxModelRetries(2)`) at its next model call once the count passes the budget. Absent on a resumed approved call's RETRY, which the loop does not count. The model-visible `RETRY: …` text is unchanged |
| `weft.panic.layer` | string | `error.type` `panic`: `handler` (the tool's own function panicked) or `middleware` (a `WrapTools` middleware around it did) |
| `weft.tool.input_error` | string | `error.type` `INVALID_INPUT` from the loop's own decode: `strict` (an argument field the schema does not declare, under `StrictInput`), `schema` (a value of the wrong type or shape), `syntax` (not one JSON value: malformed, truncated, or trailing data) |

Status: `Ok` for a result; `Error` with an empty description for an
error result (the result text is content); **unset** for a call parked
for approval (`weft.tool.pending`). A call a resume denied or left
undecided has a zero-length span marked `weft.tool.denied` (UX-E-17;
before U13.1 it had none — the root's `weft.run.denied` was its one
trace). A `Resolve`d call has no span: nothing executed.

## 4. Log records

Every weft record is one OTel log record: logger
`github.com/weftgo/weft`, an `EventName`, a body (a JSON string), a
timestamp (emission time), severity INFO (WARN for a `tool_finish` with
`is_error`), and attributes. Every record carries `weft.record` (its kind,
mirroring the EventName for backends that drop it), `weft.run.id`,
`gen_ai.agent.name` when named, `weft.content` (§5), and the run's
metadata.

**Which span a record names.** A record carries the trace and span id of
the context it was emitted on, which is not, in general, the span it
describes. `event`, `delta` and growth `messages` records go out on the
run's context, so they all carry the **`invoke_agent`** span's ids — a
`tool_start` does not carry its `execute_tool` span's, a `step_finish`
not its `chat` span's. `prompt`, `tools`, a run-scope compaction view,
`request` and `raw` go out in the model-call phase, on the **`chat`**
span's context. The session marker and the heartbeat describe no span. A
reader joins a record to its span, and records to each other, on the
weft ids of §2 — `weft.run.id`, `weft.step.index`, `weft.tool.seq` /
`gen_ai.tool.call.id` — never on span ids (absent without an SDK
anyway).

**The storage key.** A store is idempotent on (run id, kind, position):
a retried export is a no-op. Each kind has its own position attribute and
its own per-run counter, contiguous from 0 — a hole below the high-water
mark is a lost record (`gap`, §7). A record of a positioned kind without
its position attribute comes only from a malformed producer: an
`event`, `messages`, `request`, `prompt`, `tools` or `raw` record is
stored at position -1 (duplicates collapse; the readers skip it — an
event there is counted in `event_count` and never shown), never at 0,
where it would collide with the run's `run_start`. A `delta` without its
position counts as position 0: deltas are never stored, so it only
raises the delta high-water mark to 1, on both backends.

| `weft.record` | EventName | Position | Count per run | Body |
|---|---|---|---|---|
| `event` | `weft.event` | `weft.event.pos` | one per durable event | the event's wire JSON |
| `delta` | `weft.delta` | `weft.delta.pos` | one per streamed delta | the delta's wire JSON — counted, never stored |
| `messages` | `weft.messages` | `weft.messages.index` | one per transcript batch, plus compaction views | a JSON array of messages |
| `request` | `weft.request` | `weft.request.index` | one per model-call attempt | the request object |
| `prompt` | `weft.prompt` | `weft.prompt.index` | one per distinct system hash | `{"hash", "text"}` |
| `tools` | `weft.tools` | `weft.tools.index` | one per distinct catalog hash | `{"hash", "tools": [...]}` |
| `raw` | `weft.raw` | `weft.raw.index` | one per HTTP exchange, dev only | the wire request/response pair |
| `compaction` | `weft.compaction` | none: derived from `weft.compaction.hash` | one per `thread` compaction | the session marker |
| `heartbeat` | `weft.heartbeat` | none | every 10 s per open run | none — never stored |

### `event` and `delta`

The body is the core's event wire (ADR 0004), discriminated by `type`;
`weft.event.type` repeats it. Durable events, on `weft.event.pos`:

| `weft.event.type` | Body fields | Extra attributes |
|---|---|---|
| `run_start` | `id`, `model {provider, name}`, `agent`, `instructions_hash` (informational: readers take the `weft.instructions.hash` attribute, never this field) | `weft.parent.run.id`, `weft.parent.call.id` (children), `weft.manifest.hash` (named agents), `weft.instructions.hash` (always, since ADR 0028), `weft.version`, `weft.resumed_from` and `weft.resume.calls` (a resume, as on the span) |
| `step_start` | `run_id`, `index` | `weft.step.index` |
| `tool_start` | `run_id`, `seq`, `call_id`, `name`, `args` | `weft.tool.seq`, `gen_ai.tool.call.id`, `gen_ai.tool.name` |
| `tool_finish` | `run_id`, `seq`, `call_id`, `name`, `content`, `is_error` | same as `tool_start`; `weft.tool.truncated_bytes` (int) when the result cap cut the content (`weft.tool.retry` / `weft.tool.retry_budget` are on the span only, §3) |
| `step_finish` | `run_id`, `index`, `reason`, `usage`, `raw`, `latency_ms`, `ttft_ms` | `weft.step.index`, `weft.latency_ms`, `weft.ttft_ms` (when known), `gen_ai.response.model` (the model that answered) |
| `steered` | `run_id`, `seq`, `step`, `messages` | `weft.step.index` |
| `run_finish` | `run_id`, `usage`, `steps`, `pending` (parked calls), `stopped_by` (the span's `weft.run.stopped_by`; absent on runs recorded before it) | — |

`usage` is `{input_tokens, output_tokens, cached_input_tokens?,
cache_write_tokens?, reasoning_tokens?}`. Deltas (`text_delta`,
`reasoning_delta`, `tool_args_delta`) are on `weft.delta.pos`, a counter
of their own, so a dropped delta never opens a gap in the event counter.
A Subagent child's events are its own records under its own run id; the
parent's `nested` wrapper is never recorded.

A run that ended has a `run_finish` (success, or parked) **or** an
`invoke_agent` span with status `Error` (failure); a run with neither is
running or interrupted (§6).

### `messages` — the transcript and the compaction view

Attributes: `weft.messages.index`, `weft.messages.count` (messages in the
body), `weft.step.index` (the step the batch joined; 0 for the input),
`weft.messages.input = true` on index 0. The body is a JSON array of
messages (`{"role": "user"|"assistant"|"tool", "content": [parts]}`,
ADR 0001). No system role exists: the system text is the `prompt` record.

- **Growth** — a record without `weft.messages.reason`. Emitted at five
  points: the run's input (index 0), the tool message a resume creates or
  rebuilds, each assistant message, each tool message, each steered
  batch. Growth records concatenated in index order are the run's
  transcript, byte for byte.
- **View** — `weft.messages.reason = compacted`. What one request saw
  instead of the transcript (a `PrepareStep` that trimmed or summarised).
  Never part of the transcript and never counted. Extra attributes:
  `weft.messages.from_seq` and `weft.messages.to_seq` (the half-open
  range `[from_seq, to_seq)` of transcript message ordinals the view
  replaced; equal for a pure insertion), `weft.compaction.scope = run`,
  `weft.compaction.hash`: lowercase hex sha256 over the canonical JSON
  (the catalog hash's encoding, below) of the object
  `{"entries": <the view's body, decoded with number lexemes kept>,
  "from_seq": <n>, "to_seq": <m>}` — keys sorted, so `entries` first. It takes the next index on the
  same counter, right before the request record that names it. The
  messages the model saw are the growth records below the view's index,
  concatenated, with `[from_seq, to_seq)` replaced by the view's body.
- A reader skips every record with a non-empty `weft.messages.reason`
  when it builds the transcript; only a reader applying views fails on a
  reason it does not know.

### `request`, `prompt`, `tools` — what each model call was given

Emitted in the model-call phase, after `PrepareStep`, immediately before
the model is called, in the order `prompt` (when its hash is new to the
run), `tools` (when its hash is new), the view (when the messages were
rewritten), `request`. A request that was never sent is never recorded.

- `request`: attributes `weft.request.index`, `weft.step.index`,
  `weft.attempt.index` (1 for the loop's call, 2, 3, … per further
  reported attempt), `weft.system.hash` (when the request had system
  text), `weft.catalog.hash` (when tools were offered). Body: `step`,
  `attempt`, `system_hash`, `messages_ref {index?, count}` (the messages
  record the request's messages are the view as of; `index` absent when
  capture was off or a content-off destination removed it, §5), `tools {catalog_hash, names}` (names in offered
  order), `tool_choice?`, `thinking?`, `sequential_tools`, `params
  {temperature?, top_p?, max_tokens?, stop?, seed?}`, `model {provider,
  name}`, `stream`.
- `prompt`: attributes `weft.prompt.index`, `weft.system.hash`. Body
  `{"hash", "text"}`: the composed system text (instructions after
  `PrepareStep`, with the tools' prompt snippets appended). `segments?: [{source, text}]` attributes the text to its sources
  (UX-S2-11): `instructions` (after `PrepareStep`), then `tool:<name>`
  per advertised tool's snippet, in composition order — joined by the
  blank lines `composeSystem` writes they are `text` exactly, and the
  hash stays over `text`. Absent when no tool contributed a snippet.
  Content like the text: a content-off chain drops the record; a
  content-on chain redacts each segment as it redacts the text
  (`core.ContentPrompt`) and drops `segments` when its cap cut the text.
- `tools`: attributes `weft.tools.index`, `weft.catalog.hash`. Body
  `{"hash", "tools": [{name, description, schema, timeout_ms, approval,
  replay, max_result_bytes, sequential, source}]}` in name order.

**Hashes.** Every text hash is lowercase hex sha256 of the UTF-8 bytes,
taken before any destination redacts or caps the text:
`weft.system.hash` over the composed system text,
`weft.instructions.hash` over the raw configured instructions (fixed for
the run; `e3b0c442…b855`, the empty string's, when there are none). The
catalog hash (ADR 0028 §5) is lowercase hex sha256 over canonical JSON,
built in four steps:

1. Decode each tool's JSON schema keeping every number's source lexeme
   (Go: a `json.Decoder` with `UseNumber`).
2. Build one map per tool with the keys `description`, `name` and
   `schema` (the decoded value), and sort the maps by `name`. Every
   object at every level is written with its keys sorted — an emitter
   that writes a struct's fields in declaration order is wrong.
3. Encode the array with no insignificant whitespace, no HTML escaping
   (Go: `SetEscapeHTML(false)`) and no trailing newline.
4. sha256 the bytes.

Go's encoder output is the definition. An emitter starting from RFC 8785
(JCS) must honour its three differences: numbers keep their source
lexeme (`1.0` stays `1.0`, not `1`); U+2028 and U+2029 are written
escaped, `\u2028` and `\u2029`, even without HTML escaping; and invalid
UTF-8 in a string is replaced by U+FFFD. No tools offered is
`catalog_hash ""` and no `tools` record — no emitter hashes `[]`. A
stored record's step is -1 when `weft.step.index` was absent.

### `raw` — provider wire bodies (development only)

Only under `otel.RawBodies(true)` with `WEFT_ENV=dev`, only to `Local` and
`Studio` destinations with content on. Attributes `weft.raw.index`,
`weft.step.index`, `weft.attempt.index`, `weft.content = full`,
`weft.content.truncated_bytes` when a body was cut. Body `{step, attempt,
request {method, url, headers, media_type, body, encoding?, bytes,
truncated_bytes?}, response {status, headers, media_type, body,
encoding?, bytes, truncated_bytes?, complete} | null, redacted_headers,
redacted_query?}`; credentials are stripped before emission and each body
is capped at 256 KiB (ADR 0028 §12).

### `compaction` — the session marker

Emitted by `thread` when a session compaction lands, under the id of the
last run of the session that produced the compacted context.
Informational: it carries no messages and a reader never applies it (the
next run's input record already holds the compacted context). Attributes
`weft.compaction.scope = session`, `weft.compaction.hash` (lowercase hex
sha256 of the compaction entry's JSON as `thread` wrote it, its entry id
included, not re-canonicalised), `weft.content = none`,
`gen_ai.agent.name`, and the session's metadata verbatim (`weft.session.id`,
`weft.turn`, `weft.public_id`, …) — but **not** the
`gen_ai.conversation.id` / `session.id` mirrors the core adds to a run's
spans and records.
No position attribute: a store derives the position from the hash. Body
`{scope, hash, entry, reason, replaced, entries, messages_before,
messages_after, tokens_before, tokens_after}`.

### `heartbeat`

`weft/otel` emits one per open run every 10 s (`otel.Heartbeat`):
`weft.record = heartbeat`, `weft.run.id`, and a copy of the string
attributes of the run's `run_start` record (the run's metadata with its
mirrors, `gen_ai.agent.name`, the hashes, `weft.version`), no body, no
position. Never stored; it moves the run's last-seen so a quiet run reads
running instead of interrupted.

Each destination's chain adds `weft.records.dropped` (int) to its own
copy of three records once it has lost a record: the heartbeat, and the
`run_start` and `run_finish` event records (an attribute of the record,
not of the event body — the core emits neither; so every run's end
carries it, however short the run, where heartbeats come only from runs
open 10 s). The value is the cumulative count of records that
destination lost since the pipeline started — its batch queue full (a
full queue refuses deltas first, at half full; ordinary records at seven
eighths; `run_start`, `run_finish` and the heartbeat only when full), a
failed export or write, a redaction failure — policy filters (a
content-off chain's `messages`, `NoDeltas`) excepted. Absent while it has
lost none. It is not caller metadata (`obsdb.MetaOf` skips it). Studio
keeps the largest value heard per `service.name` from any of the three:
its ingest health (`/api/meta`'s `ingest.dropped` — the dev token's and
setup A's loopback, omitted for a panel token — the Settings page, `weft
doctor`). The pipeline's resource names no process (no
`service.instance.id`), so a restarted app's smaller count reads under
the earlier process's larger one until Studio restarts.

While the pipeline has a live slog bridge, every heartbeat a
destination that takes app logs receives also carries
`weft.logs.bridged` (int): the lines the bridge emitted since the
pipeline started (pipeline-wide, the same count on every such copy;
the others' copies go without it) — like the root span's mark (§3),
never metadata. Informational: no reader consumes the heartbeat's
copy today (the logs route reads the root span's).

### App log records — the slog bridge

Not weft records: they carry no `weft.record` and no `weft.run.id`, so a
store keeps them with the app's other log records (`other_logs` on
SQLite, `otel_logs` on ClickHouse) and a reader attributes them to a run
through the span they were emitted under (`obsdb.DB.OtherLogs`: the
run's own spans and the non-weft spans below them, never a child run's).
`weft/otel`'s bridge (`otel.Slog()` wraps `slog.Default`;
`otel.SlogHandler(next)` and `Pipeline.SlogHandler(next)` wrap any
handler) emits one per slog line logged under a valid span context — a
line with no span names no run and is not bridged:

| Field | Value |
|---|---|
| instrumentation scope | `github.com/weftgo/weft/otel/slog` — what the destination chains recognise a bridged line by |
| trace id, span id | the context's: the `chat` span for `mw.Log`'s lines and anything the model chain logs, the `execute_tool` span for a tool handler's (and `mw.Audit`'s), the `invoke_agent` span for `core.Logger`'s run lines |
| timestamp | the slog record's time (its emission when zero); observed timestamp the bridge's clock |
| severity number | the slog level + 9, held to 1–24: DEBUG 5, INFO 9, WARN 13, ERROR 17 |
| severity text | the slog level's name (`DEBUG`, `INFO`, `WARN`, `ERROR`, `INFO+2`) |
| body | the slog message (string) |
| attributes | the handler's and the record's slog attributes, flattened: a group's keys joined with `.` (`db.table`), an empty-keyed group inline; strings, ints, floats and bools as themselves, durations and times as their string forms, anything else its `fmt` text; every key starting `weft.` is renamed `slog.weft.…` (`weft.record`, `weft.run.id`, `weft.event.type` would make the line read — route, shape and shed — as weft's own); the first 120 kept, the rest counted in `weft.log.attrs_dropped` (int, only when some were) so the SDK's 128-attribute limit never cuts silently |
| `weft.content`, `weft.content.truncated_bytes` | the destination's content policy (below): `stripped` on a content-off destination's copy; the bytes Redact-then-MaxBytes cut on a content-on one |

Every slog level goes to the pipeline — the bridge has no level of its
own, and `core.Logger`'s and `mw.Log`'s lines are DEBUG — at the
severities some destination takes. Which destinations take them is
`otel.AppLogs`: Local and Studio with content on by default, never
Datadog, Langfuse, OTLP or Exporters unless the destination opts in with
`otel.AppLogs(true)` (an app may log anything, prompts included). The
opt-in admits the lines; it never bypasses §5's content policy, which
shapes them like a transcript field: a content-on destination applies
its `Redact` (kind `otel.ContentLog`, `"log"`) then its `MaxBytes` cap
(default 32 KiB) to the body and to each string attribute, summing the
bytes cut in `weft.content.truncated_bytes`, and drops the line when
`Redact` panics (counted as the destination's loss — never sent
unredacted); a content-off destination that opted in receives the line
stripped — body and string attribute values `""`, `weft.content`
`stripped`, its time, severity, span and other attributes kept as
metadata. Under a full queue (U5) bridged lines are shed at the delta
threshold, before weft's own records. The pipeline's own WARNs about its
destinations are never bridged.

## 5. Content policy

Content — message text, tool arguments and results, the system prompt,
the catalog — is off in the core by default and decided per destination:
on for `otel.Local` and `otel.Studio`, off for `otel.OTLP`,
`otel.Exporters` and the vendor presets. `weft.content` says what a
record holds:

| `weft.content` | Meaning |
|---|---|
| `full` | as emitted (a content-on chain may still have redacted or capped it) |
| `stripped` | a content-off destination's chain stripped it |
| `none` | the core captured none (no destination wanted content, or `weft.Content(false)`); on the session marker, which carries none by nature |

What a content-off chain does, per kind: `event` and `delta` bodies keep
their shape with the content fields emptied (`tool_start.args` → null,
`tool_finish.content` → `""`, `text_delta.text` → `""`, `steered.messages`
→ `[]`, parked calls' `args` → null) and are marked `stripped`; `messages`,
`prompt`, `tools` and `raw` records are dropped; a `request` record is
kept with `params.stop` emptied and `messages_ref.index` removed (the
destination never received the `messages` record it points at;
`messages_ref.count` stays), marked `stripped` — its hashes, names and
numbers survive. A content-on chain may cap content (`MaxBytes`) and
then sets `weft.content.truncated_bytes` (int, bytes cut) on the record;
the transcript (`messages`) is never capped. A bridged app log line
(§4) is content too: stripped by a content-off chain that takes it,
redacted and capped by a content-on one.

## 6. The run row: what a reader derives

A conforming store keeps one row per `weft.run.id` and fills it from the
spans and records as they arrive, in any order. Every rule below holds on
both shipped backends (`obsdb/sqlite`, `obsdb/clickhouse`).

**What the fixtures pin.** Every field of this table is compared, on
both backends, for every run of every generated case (§10) —
`weft_version` as the fixtures' normalised `v0.0.0-contract`, the times
on the fixtures' normalised clock (§10: per signal, not across). The rule branches they exercise:
`status` `succeeded` (most cases, `parked` with `pending` 1; from the
root span alone, no `run_finish`, in `tracer_only` and `tail_lost`),
`failed` (`failed` and `tracer_only_failed`: the span's status and
description, no `run_finish`, so `steps`, `usage` and `stop_reason` come
from the span) and `interrupted` (`interrupted`: no `invoke_agent` span,
no `run_finish`; `trace_id` from the records); `weft_version` and
`manifest_hash` from the span when no record carries them
(`tracer_only`);
`meta`, `playground`, `experiment_id` and `forked_from` (`tool_calls`);
`resumed_from` / `resumed_by` (`resumed`, `approval_denied`);
`stopped_by` from `run_finish` and the span (`stopped_by`, `parked`, every
succeeded case), from the span alone on a failed run (`failed`:
`max_steps`; `canceled`: `canceled` with `cancel_cause` `studio.cancel`),
absent where no control decided (`interrupted`, `stock_genai`,
`pre_upgrade`);
`session_id`, `public_id`, `turn` (`session_turns`); the parent link
(`subagent`). Not exercised by any fixture: `running` (a fixed-epoch
fixture's last-seen is always older than 30 s), the span fallback for
`provider`/`model` (every generated run has a `run_start`), and
`instructions_hash`'s "larger when they differ" rule — those are the
backends' own tests' to pin.

| Field | Derived from |
|---|---|
| `id` | `weft.run.id` |
| `parent_run_id`, `parent_call_id` | `weft.parent.run.id`, `weft.parent.call.id` |
| `trace_id` | the `invoke_agent` span's trace id (else any record's) |
| `service` | the resource's `service.name` |
| `agent` | `gen_ai.agent.name` |
| `provider`, `model` | `run_start`'s `model.provider`/`model.name`, or the `invoke_agent` span's `gen_ai.provider.name`/`gen_ai.request.model` (the span spells the provider in semconv form: `gcp.gemini` for the core's `google`) |
| `session_id`, `public_id`, `turn` | `weft.session.id`, `weft.public_id`, `weft.turn` |
| `playground`, `experiment_id`, `forked_from` | `weft.playground`, `weft.experiment.id`, `weft.forked_from` |
| `resumed_from` | `weft.resumed_from` (the `invoke_agent` span or `run_start`; the larger when they differ). SQLite 0018's `runs.resumed_from`, ClickHouse 0019's `weft_runs.ResumedFrom` |
| `resumed_by` | on a parked run: the latest run by start time whose `resumed_from` names it (a tie on the start goes to the larger id; never the largest id alone — a core run id is random hex, a thread turn's `-t10` sorts before `-t9`) — derived at read time on both backends (SQLite a correlated lookup over 0018's `runs_resumed_from`, ClickHouse one grouped read beside the counts over 0019's `idx_resumed_from`), never stored, so a resumer ingested before or after the parked run links it alike, no row is written for a parked run a store does not hold, and deleting the resumer unlinks it. Live, the backends differ: SQLite re-publishes the parked run's row when its resumer lands, so a live list relinks it at once; ClickHouse has no live relink — the parked chip updates on the next list read. Studio's status word reads `parked → <resumer>` from it (U1's seam) |
| `manifest_hash`, `weft_version` | `weft.manifest.hash`, `weft.version` — from any record or span of the run that carries them (the `invoke_agent` span does): a run whose records were lost, or never emitted, still names both. `weft_version`'s precedence, one on both backends: the `run_start` record's `weft.version` and the `invoke_agent` span's rank together (one core literal, so equal by construction), the larger string kept should they differ (ClickHouse's `max`, SQLite's merge); the root span's resource `weft.version` (`otel.Install` stamps it there) only when the root carries no attribute; no other span's resource ever (ClickHouse 0012 restates the traces view so, and SQLite's merge reads only the root; a row written before either from a non-root span's resource stays, on both backends — ClickHouse's 0010/0011 view and SQLite's old fill-if-empty both kept one, and neither ClickHouse's `max` nor SQLite's `maxString` can forget it — and differs only where one run's spans carried different resources) |

**Steps and tool calls.** A run's steps are its `chat` spans ordered by
`weft.step.index` (the waterfall), equally its `step_start`/`step_finish`
events; its tool calls are its `execute_tool` spans ordered by
`weft.tool.seq`, equally its `tool_start`/`tool_finish` events. The
transcript is the growth `messages` records concatenated in index order.

**A run tree** (U9.1) is a run's spans with every descendant run's: the
runs whose parent chain reaches it — each run's parent its row's
`parent_run_id` (a span with a `weft.run.id` always makes its run's row,
its `weft.parent.run.id` the row's parent, so a running child has a row
before its `invoke_agent` span ends) — and, as a fallback for a run no
row or span names a parent of, the runs core's id rule names
descendants. A reader never parses an id where a stored parent
answers: a run whose row or span names a parent outside the tree is
not in it, whatever its id. The rule is core's child id shape exactly
(`core/subagent.go`'s `childRunID`): `<parent>/<step>/<call id>`, the
step one or more ASCII digits, or `<parent>/resume/<call id>` under
Approve, the call id non-empty (`obsdb.TreeChildID`). A parent-less run
whose id has that shape under the run's id belongs to the tree, under
the nearest run above it of which the id has the shape
(`obsdb.TreeIDRule`) — a child whose `run_start` was lost and whose
spans carry no `weft.parent.run.id` is placed so; an app's own
hierarchical ids (`job/1`, `job/1/retry/2`) are not of the shape and
are never placed by it. SQLite reads the id range (`run_id > id + "/"`,
`< id + "0"`) and keeps the shape in Go; ClickHouse adds `match()` with
the same pattern to its `startsWith`. The descendants are
found from the run rows before a span is read (`obsdb.TreeMembers`) and
their spans read by run id, in any trace: a child stored under another
trace is in the tree, and the run's trace is never read whole — a leaf
of a large app-level trace reads its own subtree only. A derived run
(§9), whose spans carry no run id, is cut from its trace
(`obsdb.CutRunTree`), its descendants by their derivation's parent:
the trace's first `obsdb.TreeTraceCap` (50,000) spans in start order
are read, the subtree cut from them first and capped after, so a run
late in a large trace keeps its spans while they fall inside the read;
`RunTree.TraceTruncated` says the trace held more (Studio's second
`truncated` hole, cause `response_cap`, its reason naming the trace
cap).
Each span belongs to the run its `weft.run.id` names, else to the
derived run whose subtree holds it; a span of no run (an app's own) and
a run outside the chain and the id rule (a sibling under one app-level
trace) are not in it, nor is a `thread/pool` child session (it runs on
the pool's own context: its runs name no parent run). The tree is ordered by start, then span id,
keyed by run id + span id (`obsdb.TreeSpan`: the span, its `RunID`,
that run's `ParentRunID`), and capped at `obsdb.TreeSpanCap` (10,000)
spans, the first in start order: `obsdb.RunTree.Truncated` says the tree
holds more. `RunTree.Missing` is the descendant runs with a row and no
span in the tree that are not running (a child that ran without a
tracer, or whose spans a destination dropped; a running child has no
span yet because spans export when they end, so it is not missing),
each with its parent and public id, the first `obsdb.TreeMissingCap`
(100) by start, `RunTree.MissingCount` all of them; empty on a cut
tree. The reads are bounded by the tree's own size: SQLite's recursive
walk visits each member row once, ClickHouse issues one statement per
level a non-Subagent child opens (a chain of nested turns n deep costs
n statements), and the span read is capped. Served by `obsdb.TreeReader`
— both shipped backends: SQLite finds the rows in one recursive
statement (`runs_started` for the walk, runs' primary key for the id
rule's range) and reads the spans on `spans_run`; ClickHouse finds them
on weft_runs' primary key (the id rule, `startsWith`) and 0020's
`idx_parent_run` (one statement per level a non-Subagent child opens)
and reads the spans on `idx_weft_run_id` (0016) — and by Studio as
`GET /api/runs/{id}/spans?tree=1` (capability `spans_tree`; each span's
`run_id` and `parent_run_id`, and the tree's `holes`: `truncated`, cause
`response_cap`, past the cap (and past a derived run's trace cap);
`not_recorded`, cause `no_spans`, `runs` naming the first 100 missing
runs and `count` all of them; `hidden` when a panel token's scope left
runs out; `studio/testdata/api/spans-tree.golden.json` pins the shape). A
panel token reads the run's own spans — the run's scope decides, as on
the plain route — and each descendant whose spans (a missing one: its
row) carry the token's public id under a parent it reads; any other
descendant (a nested `Generate` or thread turn inside a tool handler
with its own session's public id, a child whose metadata cleared
`weft.public_id`) is left out with its whole subtree, unnamed, under
the `hidden` hole — never a 403 for the tree. The scope cuts before the
cap (`obsdb.TreeQuery.PublicID`): the backend reads only the runs the
rows show visible, then the spans' own public ids decide, then the cap
counts visible spans alone — a hidden run never takes a visible one's
place, nor makes the visible tree read `truncated`. `TreeReader.ChildRuns` is
`RunDetail.Children` for many parents in one read (SQLite on
`runs_started`, ClickHouse on 0020's `idx_parent_run`), in the same
order (started, then id): Studio prices a runs page's subagent trees one
read per tree level, so a row's delegated figures, reasons and unpriced
models are the run document's. The fixtures' `subagent` case pins the
parent's tree (`tree` in `expect.json`); every other case's tree is the
run's own spans alone, `RunSpans`' count.

**A session** is the runs sharing `weft.session.id` that are top-level
(no parent) and not playground runs, ordered by `weft.turn`, then
`started`; the public id resolves to its session through
`weft.public_id`. Its row's `title` is the newest turn's (by
`weft.turn`, then `started`) non-empty `weft.session.title`, `""` when
no turn carried one; its `first_prompt` is the first turn's
`prompt_preview` — `""` when that turn stored no content, never a later
turn's; its `content_off` is true when that same first turn was recorded
without content — events stored, no `messages` record, not derived —
and absent otherwise, so a list titles an untitled content-off session
"(content not captured)" rather than its id
(`obsdb.SessionRow.Title`/`FirstPrompt`/`ContentOff`; the fixtures'
`sessions`). `SessionQuery.Q` matches a term against the title, the
first turn's whole prompt, the session id, the public id and the agent.

**Manifests** (U27) are not derived from the records: a row's
`manifest_hash` is the root span's `weft.manifest.hash` (§2), and a
store that implements `obsdb.ManifestStore` (both shipped backends:
SQLite's `manifests`, migration 0014; ClickHouse's, 0016) keeps the
one-agent `core.Manifest` document under that sha256 — Studio writes it
from the weft.json it serves and from runtime registrations, never from
ingest. Content-addressed, the first write kept, and kept forever: the
run deletions and the sweep never touch it, so a run that remains
resolves its hash. The contract fixtures are record-driven and carry no
manifest; the obsdbtest `Manifests` case and Studio's
`TestRunResolvesItsRegisteredManifest` are its proof.

**What the record attributes to user code today** (UX-S1-09). The
seams where an app's own code runs — `PrepareStep`, `WrapModel`,
`WrapTools`, `Tap`, `OnMessages`, `OnRunEnd`, option composition — are
not recorded as hooks; only their effects are. What a reader can
attribute:

- `PrepareStep`: the `request`/`prompt`/`tools` records are written
  after it (§4), so a step whose `weft.system.hash` or catalog differs
  from the run's instructions (`weft.instructions.hash`) or the step
  before reads as rewritten — Studio's Request pane chips "changed by
  PrepareStep" / "catalog changed at this step", and a rewritten message
  view is a `messages` record with `view` (the "compacted" mark). Which
  `PrepareStep` did it, and why, is not recorded.
- `WrapModel`: what middleware reports through
  `core.ReportFromContext` — `attempt` spans with `weft.attempt.layer`
  (`mw.Retry`, `mw.Fallback`; §3); a middleware that reports nothing is
  invisible apart from the `chat` span's timing.
- `WrapTools`: the `execute_tool` span's outcome — `error.type`,
  `weft.panic.layer` `middleware` for a panic inside the chain,
  `DENIED` from a policy; the chain itself is not named.
- `Tap`, `OnMessages`, a failed record or report: `weft.tap.panics` on
  the `invoke_agent` span (§3), the count of contained panics, never
  which observer.
- `OnRunEnd`: nothing (it runs after the span ended; `Agent.TapPanics`
  alone counts its panics).
- Option composition: the effective configuration's hashes
  (`weft.manifest.hash`, `weft.instructions.hash`) and a run option's
  `weft.override.*` (§3); which option produced a value is not knowable
  from the record.

Naming the hook on the request record (`request.body.prepared[]`) is
U25's, and the middleware onion on the step U23's; until then the record
says what changed, not who changed it.

## 7. Badges

Every place a record is missing, cut or derived is shown with a badge
from ADR 0028 §11's closed table (`obsdb.Hole`; the words live in
`obsdb.HoleNote`). The run-level badges and how a reader decides them
(the fixtures' `holes`):

| Badge | On a run when |
|---|---|
| `not_recorded` | `instructions_hash` is `""` and `request_count` is 0: written before ADR 0028 — no request, prompt or tools records exist (`RunRow.RequestsHole`) |
| `interrupted` | the derived status is `interrupted` |
| `max_tokens` | `stop_reason` is `max_tokens` |
| `stripped` | an event record is marked `stripped` or `none` |
| `truncated` | an event record carries `weft.content.truncated_bytes` > 0 |
| `truncated`, cause `metadata_cap` | the run's `invoke_agent` span carries `weft.metadata.dropped` = N > 0 (`Problems.MetadataDropped`): "N metadata pairs dropped (limit 64 keys, 128-byte keys, 1 KiB values)" (`obsdb.MetadataCapReason`) — the core dropped them whole, never cut; the fix names the limits of the Metadata run option |
| `gap` | the event counter has a hole below its high-water mark |
| `gap`, cause `events_lost` | a weft run whose `invoke_agent` span is stored and carries `weft.run.events` = M > 0, with fewer than M events stored (`obsdb.EventsLostHole`, read through `TailLostHole`; and `LostRecordsHole` when no record at all was stored): "N of M events were lost" (`obsdb.EventsLostReason`), with how many of them are the run's tail — "the last K events were lost": positions above the highest one stored, which the counter-hole rule above cannot see — and the fix naming the knob (`otel.QueueSize`, `otel.Blocking()` in dev, the app's "destination queue full" WARN, `weft doctor`). Any status: a failed run's lost events are lost too. Raised once the run stopped settling (§6). Studio folds the counter-hole gap into this one badge's words |
| `gap`, cause `messages_lost` | a weft run whose `invoke_agent` span is stored and carries `weft.run.messages` = N, with some but fewer than N growth `messages` records stored (`message_count` > 0 and < `messages_emitted`; `obsdb.MessagesLostHole`): "K of N transcript batches were lost: a destination dropped them before they were stored (its queue full, or an export failed), so the transcript is missing the messages they carried" (`obsdb.MessagesLostReason`), with the queue fix `events_lost` names — admission sheds a `messages` record at the tier it sheds an event, so a storm can cost either. Any status; raised once the run stopped settling (§6); joined to an `events_lost` gap on the one badge when both were shed. **Not distinguished:** a content-on destination that lost *every* `messages` record of a run reads like a content-off one (which stores none by design, §5) — `message_count` 0 is never called lost, as the row carries no content-off flag (the events' own `weft.content` mark is per destination chain and is not read for this badge); that one case — a content-on run with events stored and no transcript batch at all — is left unbadged |
| `gap`, cause `tail_lost` | a weft run whose root carries no `weft.run.events` (written before U5) — its `invoke_agent` span stored and reading `succeeded`, with events stored and no `run_finish` (`obsdb.TailLostHole`'s fallback): "the run's root span ended but its run_finish record never arrived: a destination dropped the record tail, so the last steps' records are missing" — raised once the run stopped settling (§6), so a root stored ahead of its records is never called lost. Studio badges the step whose `step_finish` was dropped with the same gap (its status `ok`, not `error`) and a counted step with no event with the step gap |
| `compacted` | the run holds a run-scope view (`weft.messages.reason = compacted`) |
| `derived` | the run was built from stock spans (`RunRow.Derived`, §9): "derived from spans · no events" — that run's alone, never a weft run whose records are missing |
| `not_recorded` on the logs route only (U11.1) | not a run-level badge: Studio's `GET /api/runs/{id}/logs` holds it when the run's `invoke_agent` span is stored without `weft.logs.bridged` (§3) and no app log line is attributed to the run, no line is in its gap and the scan was not cut (`obsdb.LogPage.NoBridge`; never while the root is not stored, never for a `derived` run): "no app logs: no weft slog bridge was recorded for this run … if the app bridges slog itself, it logged nothing under this run", the fix naming `otel.Slog()` — a hint beside the empty page, so it never reads "the app logged nothing" |
| `not_recorded`, cause `no_logger` | a weft run (not `derived`, not `running`) whose spans are stored and none of its records — no event, `messages` or `request` record — and whose root says it emitted none (`weft.run.events` and `weft.run.messages` 0 or absent; `obsdb.LostRecordsHole`): "the app exported spans only"; the fix names the agent option LoggerProvider (`core.LoggerProvider`, the root package's alias) and `otel.Install`. Not raised while the run settles (§6). Studio badges every step document of such a run and its requests, tools and step request panes with the same cause (`RunRow.RequestsHoleCause`), never a step `gap`. A root that says records were emitted while none was stored reads `gap`, cause `events_lost` ("every one" lost) instead: `no_logger` is reserved for emitted = 0 |

`redacted` (reserved: the pipeline does not yet mark a redaction) and
`hidden` (a read-scoped token's view of a system prompt) are decided by
the reader's scope, not by the data.

**Status words are read-time (U1).** The stored `status` is one of
`running`, `succeeded`, `failed`, `interrupted` (§6) and nothing else:
there is no stored `parked` or `cancelled`. A reader words a row with
two more, from fields it already has: **cancelled** is `failed` with
`error_type` `cancelled` (its `cancel_cause` beside it); **parked** is
`succeeded` with `pending` > 0 while nothing is known to have resumed
the run — and **parked → tN** once its resume is known: the row's
`resumed_by` (§6, the stored link a resumer's `weft.resumed_from`
makes, read first), else a later turn of the same thread session (the
next turn in that session, which decided the calls or dropped them as
`DENIED: no decision` — after a Branch, a Rollback or a Send without a
decision it is not a resume). Its detail says "N calls decided ·
resumed in tN" only on the stored `resumed_by`; found by the next turn
alone it says "N calls · next turn tN (decided or dropped)". With no
turn to name, the word carries
the resumer's id cut to 8 characters, the whole id in the hint. A reader says "N
calls awaiting a decision" only where it looked for that turn and could
not miss it: the row has a session and the reader holds that session's
whole turn list (Studio's session page, the run header once its session
loaded, the panel's session-scoped turns). Anywhere else — a filtered or
sorted runs list, an experiment row — a session turn's park reads
"N calls pending · no resume recorded here", and a sessionless run's (a
plain `Generate`) "N calls pending · a resume, if any, is not linked
yet": a plain `Generate` is
linked only when the app resuming it passes `weft.ResumeOf(res.ID)`
(`thread` and `weft/runtime` always do), and a resumer the store does
not hold links nothing. parked is therefore "open or not yet linked",
never a claim that nobody decided. cancelled and
interrupted share the warn colour (their words differ); where the
status word already says cancelled, the `error_type` kind chip is
dropped and the kind stays in the hint. Studio and the devtools panel
draw these words from one table (`studio/web/src/lib/status.ts`), each
in one colour role (`lib/palette.ts`'s `ROLE`); the `run` host event
keeps the plain words (`parked` = succeeded with pending calls). The
sessions list's status is the newest turn's stored word (no parked /
cancelled until U16): its row carries only `status`.

## 8. The GenAI semantic conventions

weft writes the OTel GenAI conventions (semconv v1.41.0) beside its own
keys, so any GenAI-aware backend renders its traces:

| Key | Where weft writes it |
|---|---|
| `gen_ai.operation.name` | every span: `invoke_agent`, `chat`, `execute_tool` (not `attempt`) |
| `gen_ai.agent.name` | `invoke_agent`; every record |
| `gen_ai.provider.name` | `invoke_agent`, `chat`, `attempt` |
| `gen_ai.request.model` | `invoke_agent`, `chat`, `attempt` |
| `gen_ai.response.model` | `chat`, `attempt` (on success); the `step_finish` record |
| `gen_ai.response.finish_reasons` | `chat` |
| `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens` | `invoke_agent` (run totals), `chat` (the call's) |
| `gen_ai.usage.cache_read.input_tokens`, `gen_ai.usage.cache_creation.input_tokens`, `gen_ai.usage.reasoning.output_tokens` | same, when non-zero |
| `gen_ai.tool.name`, `gen_ai.tool.call.id` | `execute_tool`; `tool_start`/`tool_finish` records |
| `gen_ai.conversation.id` | every span and record the core emits for a run with a `weft.session.id`, and its heartbeats (its mirror; `session.id` too) — not `thread`'s session compaction marker (§4) |
| `error.type` | failed spans |

weft never writes the conventions' opt-in content attributes (the input
and output messages on spans): content travels in log records under §5's
policy.

## 9. Deriving a run from stock spans

An application that exports **stock** GenAI spans — a Python or
TypeScript agent instrumented by the OTel GenAI conventions, with no
`weft.*` attribute anywhere — gets runs too. This section is the contract
devtools-plan item I1.2 implemented: `obsdb.DeriveStockRuns` is the one
derivation both backends write through, the `stock_genai` fixture its
executable form and `obsdbtest`'s `DerivedStock` case its edges (nested
roots, an agent without a conversation id, exports arriving children
first, a retried export, deletion).

**Which spans make a run.** A *root* is a span that has
`gen_ai.operation.name = invoke_agent` (or, without the attribute, a name
starting with `invoke_agent`), has no `weft.run.id`, and carries
`gen_ai.conversation.id`. Each root is one derived run. Its *subtree* is
the spans under it by parent span id, down to (not into) any nested root.
An `invoke_agent` span **without** `gen_ai.conversation.id` is not a
root, wherever it sits: it opens no run, and the `chat` and
`execute_tool` spans under it count toward the enclosing root's run
(its steps, its tools, its usage fallback) as if the inner agent were
part of it. A stock span tree with no conversation id anywhere stays a
trace only (`/api/traces/{id}`), as today. A span that carries `weft.run.id` is never
derived, and the subtree stops at it as at a nested root: weft's own rows
always win, so a weft run's spans — which carry the GenAI mirrors,
`gen_ai.conversation.id` among them — never make a derived twin.

A span's operation is its `gen_ai.operation.name` (an empty value is
unset); without the attribute, its name: starting with `invoke_agent` or `execute_tool`, or `chat` alone
or followed by a space (the conventions' `{operation} {model}` name — a
bare prefix would take a `chatbot` span for a model call). A span counts
toward a root only through a complete chain of stored parents: one whose
chain reaches a parent not stored (yet), or no parent at all, belongs to
no run until the missing span arrives. So a run whose spans arrive over
several exports — a `BatchSpanProcessor` exports children before the root
that ends after them — converges: re-derived from more spans, its steps,
usage and last-seen only grow, and the full tree's answer does not depend
on the order the exports came in (one exception, ClickHouse's: a root
that names no model takes its first `chat` span's, and should an earlier
`chat` span naming another model arrive in a later export than the root,
the table's `max` keeps the larger name where SQLite keeps the earlier
span's). The writers re-derive a trace from all
its stored spans whenever an export brings a span without `weft.run.id`
whose operation is one of the three; a trace of other spans costs no read.

**Derivable fields** (the run row of §6, filled from spans alone):

| Field | Derived as |
|---|---|
| `id` | `otel-<trace id>-<root span id>` (lowercase hex): deterministic from the spans, so a retried export lands on the same row. It never contains `/` and cannot collide with a generated weft id (a plain run's is 32 hex digits, a `thread` turn's `-t<n>` suffix is not hex, a Subagent child's contains `/`); a caller-chosen `core.RunID` must not use the `otel-` prefix (§2) |
| `derived` | `true` — the run row says it was built by the reader |
| `trace_id`, `service` | the root's trace id and resource `service.name` |
| `agent` | the root's `gen_ai.agent.name` |
| `provider`, `model` | the root's `gen_ai.provider.name` and `gen_ai.request.model`, else the first `chat` span's |
| `session_id` | the root's `gen_ai.conversation.id`: the conversation is the session, its derived runs its turns |
| `parent_run_id`, `parent_call_id` | for a root nested under another root's subtree: that root's derived id, and the `gen_ai.tool.call.id` of the nearest `execute_tool` span above it. A stock root under a weft run's tool is top-level — the walk stops at weft spans, so it has no parent — and its session is its own `gen_ai.conversation.id`, not the weft run's: Studio lists it as a conversation of its own |
| `started`, `finished` | the root's start and end |
| `last_seen` | the latest time of anything in the subtree: the root's end for a well-formed tree |
| `status`, `error` | `failed` with the status description when the root's status is `Error` (with no description, the error reads "the root span's status is Error (no description)": a failed run never has an empty error), else `succeeded` (a root span is exported only when it ended, so a derived run is never running or interrupted — §6's root-span rule for weft runs, which a derived run meets by construction) |
| `usage` | the run's **own** usage (when no root or `chat` span of it carries any `gen_ai.usage.*` key, the row reads zero and Studio reads its cost **unknown**, "the stock spans report no usage", never a known $0 — the fold cannot tell such a run from one whose spans report zero tokens, which reads the same): the root's `gen_ai.usage.*` when present, taken as the root's own figure; else the sum over the subtree's `chat` spans — the subtree stops at nested roots, so a nested root's calls count toward it, never toward the parent (below) |
| `steps` | the number of `chat` spans in the subtree |
| `chat` (the waterfall) | the subtree's `chat` spans in start order; a span's step is its ordinal (0-based); model, response model, finish reason and usage from its `gen_ai.*` keys |
| `tools` | the subtree's `execute_tool` spans in start order: `gen_ai.tool.name`, `gen_ai.tool.call.id`; `seq` the 1-based ordinal; `step` the step of the latest `chat` span that started before it (none when no `chat` span did) |
| `holes` | `derived` |

A derived run's spans (`DB.RunSpans`) are its subtree, read from its trace
at read time — no stored span names a derived run — in start order, with
the reader's positions under weft's own keys: `weft.step.index` on each
`chat` span (its step) and `execute_tool` span (its step, when it has
one), `weft.tool.seq` on each `execute_tool` span, and
`gen_ai.operation.name` on both — the operation the derivation resolved,
from the span's name when the producer set none or set it empty — so a
reader that switches on the attribute sees what the derivation saw. The producer's spans
are stored as exported; the numbers are stamped on the copy a read
returns, and the run's `derived` badge says who numbered them. Deleting a
derived run deletes its subtree's spans (a nested root's run is its child,
deleted with it). Deleting a weft run deletes the non-weft spans under it,
a stock agent under its tool among them — and that agent's derived row
too (it is no child of the weft run, the walk stopping at weft spans, but
it would otherwise outlive every span it was derived from); a retention
sweep counts it among the runs it deleted.

**Usage and cost of derived children.** A derived run's usage is
own-only by contract. Studio's cost split subtracts from a parent's
usage only its core Subagent children — the runs whose id is
`<parent id>/…`, whose usage the core rolled into the parent's — and a
derived child's id is `otel-…`, never of that form: a derived child is
neither subtracted from its parent nor counted as its delegated cost
(like any run linked only by `weft.parent.run.id`); it carries its own
figure on its own row. So the parent's figure must be its own. What
I1.2 implements:

1. When the root carries any `gen_ai.usage.*` key, those keys are the
   derived row's usage verbatim. A producer whose root reports totals
   that include its nested agents' usage is reported **as-is**, with no
   correction — the reader cannot tell a total from an own figure — and
   that parent's cost then includes its children's a second time; the
   producer's numbers, shown as given.
2. Otherwise the usage is the sum of `gen_ai.usage.*` over the `chat`
   spans of the root's subtree, nested roots' subtrees excluded (each of
   those is its own run's).
3. No correction is applied in either direction: no subtraction of
   children from a parent, no roll-up of children into it.

**Not derivable** — and shown so, never as an empty pane: events (no
`event` records: `event_count` 0 and `delta_count` 0, no event stream), the transcript and
the chat view's message bodies (no `messages` records: `message_count` 0),
the request, prompt and catalog (no `request`/`prompt`/`tools` records:
`request_count` 0, `instructions_hash` and `catalog_hash` `""`), `turn`,
`public_id`, `stop_reason`, `pending`. The run carries the `derived` badge
("derived from spans · no events") in place of `not_recorded`: the
records are absent because the producer is not weft, which `derived`
already says — "upgrade weft" would be the wrong fix. The words are the
table's cause `stock_spans` of `derived` (`obsdb.HoleNoteFor(HoleDerived,
CauseStockSpans)`), its fix naming this document; `RunRow.RequestsHole`
reads `derived` for a derived row, so every reader of the reading table
badges it so.

**What Studio answers for a derived run.** `/api/runs` and `/api/search`
list it (`derived: true`, `requests_badge: derived`; searchable by agent,
model and error text); `/api/sessions` groups it under its conversation
id; `/api/runs/{id}` is the row with one hole, `derived`, in the words
above; `events` and `transcript` are empty with that badge (`transcript?step=N`
is 409 with it); `spans` are the real spans (the waterfall);
`requests` and `tools` are empty with the `derived` badge in those words;
`export` carries the row and the spans, every other block badged, and
refuses `format=wefttest` 400 with the badge, as the playground's fixtures,
preview and run routes refuse a derived source (the preview and run routes
after the panel token's rules and before any check of the command's
content — its ids included — so one body gets one answer): there is no transcript to replay;
`/api/diff` with a derived side marks every column `unknown`, never a
change except unequal step counts (`missing`).
`steps/{n}` is the step's `chat` span: its times and usage (priced like
any step's; unknown when the span carries no `gen_ai.usage.*`), its
`execute_tool` spans as calls badged `derived` (no arguments or results;
`call_id` `""` for a span without `gen_ai.tool.call.id`, which is only
recommended), `request` and `messages_in` the badge, and one hole,
`derived` — never a `gap` or `not_recorded`. A Studio over ClickHouse
announces derived rows on the live lane as SQLite's hub does (the
receiver re-reads the trace's derived runs after each export). A panel token never reaches a derived run: it has no public id. Its session id
is the stock app's `gen_ai.conversation.id`, which may collide with a weft
session's id; a panel token's session view, sessions list and session cost
are then its public id's turns alone (the runs list's rule), never the
derived rows sharing the id — the server token sees them all. The
sessions list is scoped in the query (`obsdb.SessionQuery.PublicID`, a
`WHERE` on the runs before the grouping, both backends): each row's
turns, usage, first/last seen, agent and status, the list's ordering,
`total` and paging cursor (`before`, `next_before`) are the token's
view — a newer colliding derived run neither sorts the session nor
becomes the cursor, and a page holds `limit` rows while more match. A
row whose runs the cost walk cannot read whole (a read error, past the
10,000-run walk) is served with its scoped aggregates and an unknown
cost, as the server token's is.

A session a panel token lists is one it may open: the session view (and
the live stream's `session=` selector) admits the token when **any** of
the session's top-level turns carries its public id — the list's
`WHERE` — and serves those turns alone, so a session whose turns carry
two public ids (hand-set session metadata, a colliding app) is each
public id's own view of it. The server token's `/api/sessions?public_id=`
row is the same one scope throughout: its turns, usage and cost are that
public id's runs.

A known gap, left for a later decision: a session's turn sent from
inside another run's tool handler is recorded as a child run of the
enclosing run (`parent_run_id` is that run, through the core's
parent-run linkage, as every run started under a run's context is), and
the session views list top-level turns only — so that turn appears in no
session view (its session has no page of its own); the enclosing run's
page reaches it.

Runs are ordered by `started`, then id. Times are RFC 3339 UTC.

**Normalisation.** The generated cases are real pipeline output, made
byte-stable so that `go test ./obsdb -run 'TestContract$'
-update-contract` with no code change leaves `git diff` empty:

- the export is folded to one resource and scope block;
- no raw time decides a position — a span ended on a tool's goroutine
  and the loop's `tool_finish` record race, so any ranking of raw times
  (distinct values, or slots with a tiebreak) flips between
  regenerations on a coarse clock such as macOS's µs one. Each signal
  keeps the order it has by construction, on a 1 ms grid from the case's
  epoch (2026-10-01T09:00Z plus one minute per case): records in arrival
  order (the logs pipeline exports first in, first out), time and
  observed time equal; spans depth-first from the roots, siblings in
  structural order (run id shape, step, `chat` before `execute_tool`,
  attempt, tool seq, name), each span's start, events, children, end
  taking successive slots, and listed by start. Within a signal every
  ordering is the run's own; across the two the times are not
  comparable — a span and a record may share a time — so the timeline
  is not the run's, while `started`, `finished` and `last_seen` (min and
  max) are stable, no measured duration survives, and the status reads
  as it would long after the run;
- measured durations (`weft.ttft_ms`, `weft.latency_ms`, `step_finish`'s
  `latency_ms`/`ttft_ms`) read 1 where set;
- `weft.version` and the instrumentation scope's version read
  `v0.0.0-contract`, so `weft_version` is that and a release never
  changes a fixture;
- ids are renumbered in first-seen order with their shapes kept: trace
  ids `7ace…<n>` (32 hex), span ids `5ba0…<n>` (16 hex), run ids
  `a110…<n>` (32 hex), `thread` session ids `01K…<n>` (26 characters),
  so derived ids keep their form (`<run>/0/call_1`, `<session>-t2`);
- `weft.manifest.hash` (span and record attributes, so `manifest_hash`)
  is renumbered the same way, to `3a21f…<n>` (64 hex): the manifest names
  each tool's definition `file:line`, so the real hash moves whenever the
  generator's source does.

Every generated case keeps each step to at most one tool call: a
parallel batch's `tool_finish` order is the run's own race (the
handlers finish in whatever order they finish), so a case with
`Parallelism` > 1 and several calls in one step would churn on every
regeneration.
